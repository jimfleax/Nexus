# Nexus — Agent Guide

## Structure

npm-workspaces monorepo with three packages:

| Workspace         | Path              | Stack                                                    | Port |
| ----------------- | ----------------- | -------------------------------------------------------- | ---- |
| `@nexus/api`      | `apps/api`        | Fastify 5, Mongoose 9, Zod, tsx                          | 8080 |
| `nexus-workspace` | `apps/web`        | Next.js 16, React 19, TanStack Query, Tailwind 4, shadcn | 3000 |
| `@nexus/shared`   | `packages/shared` | Zod schemas + domain types                               | —    |

`@nexus/shared` is consumed by both api and web. Build it first if you change its types/schemas.

## Dev servers

```bash
./run.sh              # starts api + web, waits for health
./run.sh -p           # prettier --write
./run.sh -l           # eslint
./run.sh -p -l        # prettier then eslint
```

Or individually: `npm run dev` inside `apps/api` or `apps/web`.

API expects `MONGODB_URI` (and other env vars) in `apps/api/.env`. Web expects `API_URL` + auth secrets in `apps/web/.env`. Both have `.env.example` files.

## Commands

```bash
# From repo root
npm run build:all      # build all workspaces (builds shared first in Docker context; locally run shared build manually if needed)
npm run lint:all       # lint all workspaces
npm run test:all       # run all tests (vitest in api + web)

# Single workspace
npm run dev -w apps/api
npm run test -w apps/api          # vitest run (all api tests)
npm run test -w apps/web          # vitest run (web hooks/lib/route tests)
npx vitest run tests/health.test.ts   # single test file (from apps/api)

# Lint targets (from run.sh — lint each workspace from its own dir for config resolution)
# apps/web:  eslint app components lib hooks auth.ts proxy.ts next.config.ts
# apps/api:  eslint src
# packages/shared: eslint src
```

## Auth flow

- Auth is JWT-based (jose), not Auth.js session-based despite the naming.
- API token from the `Authorization: Bearer` header, else falls back to the `nexus-session` cookie.
- Session stored as `nexus-session` HttpOnly cookie, verified with `AUTH_SECRET`.
- API auth plugin (`apps/api/src/auth.ts`) skips `/health` and `/api/auth/*`.
- Dashboard layout (`apps/web/app/(dashboard)/layout.tsx`) verifies the cookie server-side and redirects to `/signin` if invalid.
- 401 on the client auto-signs out via `apps/web/lib/axios.ts`.

## Tenant isolation (API)

All Mongoose queries go through `tenantIsolationPlugin` (`apps/api/src/db.ts`), which injects `ownerId` from `AsyncLocalStorage` automatically. Use `{ skipTenant: true }` only for cross-tenant operations (e.g., garbage collection).

## Proxy

Next.js rewrites (`apps/web/next.config.ts`): unmatched `/api/*` requests fall through to the Fastify backend. Next.js Route Handlers at `app/api/` shadow backend routes when they exist.

## Testing

- API tests use **Vitest** + `mongodb-memory-server` (real Mongo in-process).
- Tests are in `apps/api/tests/`. Pattern: standalone Fastify instances with `app.inject()` — no external services needed.
- API `vitest.config.ts` sets `fileParallelism: false` — don't re-enable parallelism, it triggers flaky transaction errors under memory-server replica sets.
- Web also has a vitest suite (`apps/web/vitest.config.ts`) covering hooks, libs, and Route Handler tests.

## Lint / Format

- **Pre-commit** (via Husky + lint-staged): runs Prettier on all staged files.
- **Prettier** config: `.prettierignore` excludes `.next`, `dist`, `.env*`, `.scratch`, `prd`, `docs`.
- **ESLint**: web uses Next.js config (`eslint-config-next`), api uses flat config with `typescript-eslint`. Both enforce `--max-warnings 0`.
- `components/ui/**` is excluded from web linting (shadcn-generated).

## Gotchas

- The `apps/web/AGENTS.md` file is auto-generated by `next dev` — do not edit or commit changes to it.
- Shared package `dist/` must exist for the API to import `@nexus/shared`. Run `npm run build -w packages/shared` after schema changes.
- Docker builds: `docker build -f apps/api/Dockerfile .` from repo root (multi-stage: deps → builder → runner).
- GC runs on every `/health` hit, sweeping stale pending resources older than 30 min.
